- 2026-10-25 · агент C · типы контракта v3 не менялись (аддитивных правок нет). Договорённости реализации: **Хорриот** — `useHorriot` считается локально и работает офлайн (`app/src/reports/horriot.ts`): `connection` из `horriot_connections`, `records` по убыванию даты и номера, `reconciliation` — по группам на сегодня: `book_heads` = `balanceOn(movements, today)`, `horriot_heads` = Σ регистраций − Σ выбытий с `registered_on ≤ today` (не ниже нуля по группе), `diff = book − horriot`; в таблицу попадают только группы, где одно из значений не нулевое, в порядке экрана «Скот»; `pending_count` — число записей журнала поголовья без записи в Хорриоте (по `source_movement_id`). `useHorriotConnect` — `connected_demo` + `synced_at`; `useHorriotRefresh` («Передать данные») без подключения бросает `Error` «Хорриот не подключён. Сначала подключите демо-режим», иначе создаёт записи `УЧ-ХР-NNN` из журнала (идемпотентно; `registered_on` = дата записи журнала; причины: «Начальный остаток», «Рождение», «Покупка», «Поступление из другого хозяйства», «Продажа», «Продажа на убой», «Забой», «Падёж», «Передача в другое хозяйство»). Уже созданные записи при правке/удалении события журнала не меняются — это и даёт ненулевое `diff` в сверке. Серверный двойник — `POST /v1/horriot/sync` (`/api/horriot/sync`). Таблицы `horriot_*` в синхронизации помечены `optional`: пока миграция v3 не применена, синхронизация остальных данных не ломается. PDF выписки (`HouseholdExtract.url`) содержит раздел «Сведения ФГИС ВетИС «Хорриот» (учебные)»: статус, дата синхронизации, таблица «книга / Хорриот / расхождение» по группам, пометка «учебный режим». **Админ-панель** — `useIsAdmin`/`useAssistantModelSettings`/`useAssistantModelOptions`/`useUpdateAssistantModelSettings` ходят на Node-сервер (`EXPO_PUBLIC_API_URL`, `/v1/admin/me`, `/v1/admin/assistant-settings`, `/v1/admin/models`) с токеном пользователя и требуют сети. `useIsAdmin`: офлайн, ошибка, нет адреса сервера или не админ → `data = false`, `error = null`. Остальные: `Query.error` по-русски («Нет подключения к сети. Настройки модели доступны только онлайн» и тексты сервера), `fromCache` — если данные остались от прошлой загрузки. Кеш в памяти на сессию: права — 60 с, настройки — перечитываются при каждом открытии экрана, список моделей — 10 мин (так же на сервере); `useUpdateAssistantModelSettings` проверяет на клиенте непустую модель, ≤ 3 запасных и отсутствие повторов, не-админу сервер отвечает 403 «Менять модель помощника могут только администраторы». `GET /v1/admin/models` возвращает `{ models: AssistantModelOption[] }`, отсортированный по названию. **Сервер** — помощник работает через OpenRouter: `/health` → `providers.llm: 'openrouter' | 'rules'` и `model`; ответ `/v1/assistant/messages` дополнительно содержит `engine` и `model_used` (только если отвечала LLM; клиентский слой пока их не использует); модель берётся из БД (RPC `get_assistant_model_settings`, кеш 30 с), при ошибке — `OPENROUTER_MODEL`. Миграция `supabase/migrations/20261025000000_v3_horriot_admin.sql` написана, но **не применена**.
